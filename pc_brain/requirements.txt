# MOSS 多模态大脑（阶段 9–19）依赖
# 安装：pip install -r requirements.txt
#
# 这些包按"阶段"分组，你可以只装需要的那几行。全装一遍最省事。
#
# ---------------------------------------------------------------- 核心（阶段 9–10）
# 注意：OpenCV 必须锁在 5.0 以下。
#   opencv-python 5.0 起**不再自带人脸检测模型**（cv2.data 里一个 xml 都没有），
#   人脸识别会直接瘫痪；4.x 自带 17 个 haarcascade 模型文件。
opencv-python>=4.9,<5
numpy>=1.26
pyserial>=3.5
sounddevice>=0.4.6

# ---------------------------------------------------------------- 语音层（阶段 11）
# 播放用的是 Windows 自带的 MCI（ctypes 调 winmm.dll），**零依赖**。
# 只有 edge-tts 这一个新依赖，且只在 --tts edge / auto 时才需要。
# 不想装也行：--tts sapi 用 Windows 内置语音，离线可用。
edge-tts>=6.1

# ---------------------------------------------------------------- 听觉理解层（阶段 12）
# faster-whisper 只在 --asr whisper / auto 时才需要（--asr api 不需要它）。
# 它自带 ctranslate2（推理）、onnxruntime（VAD）、av（PyAV，读 mp3/m4a 等音频文件）。
# 注意：**模型本身不是 pip 装的**，首次运行会从 hf-mirror.com 下到
#       ~/.cache/moss_asr/（tiny 75MB / small 484MB，见 asr.py --list-models）。
faster-whisper>=1.0

# whisper 中文经常输出繁体（"開放時間"），用它转简体（"开放时间"）。纯 Python，很小。
zhconv>=1.4

# ---------------------------------------------------------------- 记忆 + 工具（阶段 13）
# 好消息：**零新依赖**。
#   memory.py     —— 存的是 JSON，用标准库 json / os / threading
#   moss_tools.py —— 查天气用 urllib 打 wttr.in（免费、不要 Key）
# 也就是说阶段 13 这两个能力，装不装新包都能用。
#
# ---------------------------------------------------------------- 回声消除（阶段 17）
# 还是**零新依赖**。
#   aec.py —— 就靠 numpy（已经在上面了）。自适应滤波器是自己写的（PBFDAF）。
#   本来最省事的做法是上 webrtc-audio-processing 或 speexdsp，但这两个在
#   Windows 上没有现成的 pip 轮子，要自己编 —— 对一个"离线、可验证、零折腾"
#   的项目来说，不如自己写一个能完全看懂、能跑离线的。
#   解码参考信号（mp3→PCM）复用 faster-whisper 带的 av（PyAV）。
#
#   tools/aec_live.py 用 sounddevice 放/录（上面已有）。
#   注意：它只是 **可选的实测工具** —— 平时跑 moss_brain 完全用不到它。
#
# ---------------------------------------------------------------- 强视觉（阶段 18）
# 第三次**零新依赖**，而且这一次是刻意选出来的。
#
#   要跑 YOLO，最顺手的写法是 `pip install ultralytics` + `YOLO("yolov8n.pt")`，
#   一行就完事。没这么干，因为它会一起拖进 **PyTorch（2 GB+）**。
#
#   而推理真正需要的 onnxruntime **本来就在** —— 它是上面 faster-whisper
#   的依赖（用来做 VAD），阶段 12 就装好了。所以只要拿到一个 .onnx 文件，
#   目标检测这件事就完全免费。
#   同理，非极大值抑制(NMS)用 OpenCV 自带的 cv2.dnn.NMSBoxes，
#   不需要 torchvision。
#
#   ⚠️ 模型文件**不走 pip**，要单独下（12.2 MB）：
#        python vision.py --list-models
#        python vision.py --download          # 落到 ~/.cache/moss_vision/
#      走 hf-mirror.com 而不是 huggingface.co，和阶段 12 下 whisper 模型
#      同一个理由：本机连不上 GitHub，国内直连 huggingface 也不通。
#      下完前先写 .part 再 os.replace，所以断网不会留下一个"看着存在、
#      其实是坏的"模型文件。
#
#   不下也能跑：--vision-model auto 会自动降级到 haar（只认人脸），
#   再不行降级到 null（只测运动），并且把原因写在启动横幅的「识别」那行。
#   视觉是锦上添花，让它拖垮听觉和对话是最糟的失败方式。
#
# ---------------------------------------------------------------- 变化感知（阶段 19）
# 第四次**零新依赖**。
#   presence.py —— 迟滞 + 个数确认 + 暖机，全是几十行的纯 Python，
#   连 numpy 都不用（它处理的是"每个类几个"，不是图像）。
#
#   这里其实有过一个"要不要上库"的诱因：目标检测会**闪**，
#   而"从抖动的逐帧结果里提取稳定状态"是个经典问题，有现成的做法
#   （卡尔曼滤波 / 匈牙利匹配做目标跟踪 / 各种多目标跟踪库）。
#   没上，因为这里要的东西比跟踪小得多：
#   我们**不需要知道"哪个框是哪个"**，只需要知道"这个类现在有几个"。
#   为这个小需求引入一个跟踪库，换来的是一堆看不懂、也没法离线
#   拿假序列喂的参数。
#
#   顺带说明：它跑在视觉线程里、跟在检测后面，实测 0.0176 ms/次检测
#   （一次目标检测 50~70 ms），占 0.03% —— 可以当它是白送的。
